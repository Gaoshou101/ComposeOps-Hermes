# 整体产品改进需求

## 目标

在保持现有 Docker/Compose、Agent 单通道和中文暗色工业风基础上，完成一次可验证的产品级收敛：

1. GitOps 不再把用户输入拼接进 shell；指标/告警及历史查询必须遵守纳管项目与当前 Docker 节点边界。
2. 实时页面切换和组件停用时停止 WebSocket、SSE、轮询及后台任务轮询；流式请求支持 AbortSignal。
3. 批量高风险操作使用统一确认组件，操作中心展示可恢复的错误状态。
4. Agent 工作台与抽屉共享同一执行状态，工具轨迹、确认卡和失败反馈更清晰。
5. 移动端导航降低入口密度，Agent 移动端优先聊天，会话通过抽屉/面板管理。
6. 逐步消除独立页面的旧视觉 token，统一基础按钮、卡片、模态、排版与节点上下文。

## 范围与取舍

- 本轮直接实现 P0/P1 和低风险高收益的 P2 UI 收敛；不重写所有业务页面，不新增第三方 UI 库。
- GitOps 当前 API 实际是仓库同步，因此 UI 文案先改为“同步”，不在本轮隐式新增部署行为。
- 继续保留已有会话批量删除接口，重点改善移动端发现性、执行中提示和部分失败语义。
- 任何危险操作不改变后端动作含义，只改善确认、取消、错误与可观察性。

## 验收标准

- 前后端构建、单测和 lint 通过。
- GitOps 的 clone/fetch/reset/log/checkout 使用参数数组；branch、commit、本地路径有校验。
- 指标所有容器入口拒绝未纳管项目或错误节点的容器。
- 离开 Services/Operations 页面不会遗留连接和轮询；重新进入只产生一组订阅。
- `streamComposeControl` 接受 signal，页面停用可中断请求。
- 移动端可通过“更多”访问全部导航，Agent 页面默认先显示聊天。
