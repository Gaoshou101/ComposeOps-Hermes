# 改造需求

用户要求根据此前 UI/UX 审计方案直接改进项目，并推送 GitHub。此次范围聚焦高价值、可验证的用户问题：

1. Agent 会话列表支持多选、全选、批量删除，并保留危险操作确认。
2. Agent 工作台与全局抽屉共享消息、session、流式状态和确认门，避免两个独立会话。
3. 服务卡片 AI 诊断入口正确传递项目/容器上下文并启动诊断。
4. Agent 执行历史消费后端真实 plan 数据，改名为执行轨迹。
5. 历史指标使用真实序列和异常检测，统一毫秒时间戳、网络/磁盘数值与单位。
6. Compose 语义校验或变更预览失败时阻断保存，提示重试；禁止静默绕过安全门。
7. Docker 节点测试连接不得持久化新节点或未确认编辑。
8. 补齐关键错误反馈、移动端指标布局和 Agent Inspector 的移动端入口。

约束：保持中文 UI、现有 hash router、`0.0.0.0:28765:3001` 不变；不改 dotenv/protocol 镜像文件；只使用现有 API/组件模式，必要时补充针对性测试。
