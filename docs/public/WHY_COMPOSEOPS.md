# Why ComposeOps

## 为什么不是另一个 Docker 面板

ComposeOps 的目标不是替代所有运维平台，而是成为个人服务器场景下的 AI 运维工作台。

## ComposeOps vs Dockge vs Portainer

| 能力 | ComposeOps | Dockge | Portainer CE |
|------|------------|---------|--------------|
| Docker Compose 管理 | ✅ | ✅ | ✅ |
| AI 运维 Agent | ✅ | ❌ | ❌ |
| Agent 执行操作 | ✅ | ❌ | ❌ |
| Approval Gate | ✅ | ❌ | ❌ |
| 长期记忆 | ✅ | ❌ | ❌ |
| 运维工作流 | ✅ | ❌ | ❌ |
| 数据卷备份 | ✅ | ❌ | 部分支持 |
| 多节点管理 | ✅ | ❌ | ✅ |
| GitOps | ✅ | ❌ | 部分支持 |

## 核心价值

1. 让 Agent 真正参与运维，而不仅仅是聊天。
2. 所有高风险操作必须经过确认。
3. 面向个人服务器和自托管用户优化。
4. Docker Compose 优先，而不是 Kubernetes 优先。

## 最适合的人

- Homelab 用户
- VPS 用户
- 自托管爱好者
- 希望把运维经验沉淀为工作流的人
